# PayFlow — Skaffold Workflow

## Overview

Skaffold is used to automate the local Kubernetes development and deployment workflow for PayFlow.

It coordinates application testing, Docker image building, image tagging, and Kubernetes deployment.

The goal is to make the deployment process repeatable and ensure that the application is tested before deployment.

---

## Deployment Workflow

```text
Maven Tests
     |
     v
Docker Image Build
     |
     v
Image Tagging
     |
     v
Kubernetes Manifest Deployment
     |
     v
Rollout Verification
```

---

## Maven Test Gate

The Maven test gate is intended to prevent deployment when the application tests fail.

The expected workflow is:

```text
Maven Tests
     |
     +---- Tests Fail ----> Deployment Stops
     |
     v
Tests Pass
     |
     v
Docker Build
     |
     v
Kubernetes Deployment
```

The test gate should be considered verified only after a successful test run and a deliberate failed-test validation.

### Test Commands

```powershell
.\mvnw.cmd test
```

Run the test suite from the project root.

### Verification

Record the following:

* Test command used.
* Test result.
* Number of tests executed.
* Whether the Docker build was triggered.
* Whether Kubernetes deployment was blocked when tests failed.

## Docker Image

The PayFlow release image is:

```text
07rochak/payflow:1.1.0
```

The supporting Docker images are:

```text
07rochak/payflow-postgres:latest
07rochak/payflow-redis:latest
```

These tags represent the Docker Hub image naming convention.

Skaffold may generate different tags during deployment.

Do not assume that every Kubernetes Pod runs the Docker Hub release tag. The actual deployed image must be checked using the Kubernetes Deployment configuration and Skaffold output.

---

## Skaffold Command

```powershell
skaffold run
```

This command runs the configured Skaffold deployment workflow.

The workflow may:

1. Build the application image.
2. Generate an image tag.
3. Deploy Kubernetes manifests.
4. Wait for configured deployment verification.
5. Report the deployment result.

The exact behavior depends on the current `skaffold.yaml`.

---

## Image Tagging

Two image identification mechanisms are used:

| Image type                     | Example                                   |
| ------------------------------ | ----------------------------------------- |
| Docker Hub application release | `07rochak/payflow:1.1.0`                  |
| Supporting images              | `07rochak/payflow-postgres:latest`        |
| Skaffold-generated image       | Generated automatically during deployment |

Skaffold-generated tags should be treated as deployment-specific identifiers.

The Docker Hub release version should not be confused with the tag generated by Skaffold.

---

## Deployment Verification

After running Skaffold, verify:

```powershell
kubectl -n payflow get pods
```

```powershell
kubectl -n payflow get deployments
```

```powershell
kubectl -n payflow rollout status deployment/payflow
```

The actual Deployment name must match the final manifest.

---

## Scope

This workflow is intended for local Kubernetes development and deployment.

It is not a replacement for a production CI/CD system.

Production deployments would require additional controls such as:

* CI test execution.
* Image vulnerability scanning.
* Registry security.
* Deployment approvals.
* Rollback procedures.
* Environment-specific configuration.
